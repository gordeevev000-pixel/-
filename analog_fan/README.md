# Веер аналогов (1m)

Для текущей минуты ищет в прошлом ~300 самых похожих ситуаций и показывает, как цена шла
следующие 15 минут: медиану и полосы 50% / 80% в ATR, вероятность «+1 ATR раньше −1 ATR»,
ожидаемый ход, число «живых» аналогов по мере того, как минуты проходят.
Это распределение исходов, а не прогноз.

## Запуск на своих данных

```bash
pip install -r requirements.txt

# 1. данные и отпечатки: CSV с колонками time, open, high, low, close, volume
#    src_tz — пояс времени в файле (MT4 обычно EET), market_tz — пояс рынка для «времени суток»
python scripts/stage1_data.py path/to/data.csv EET America/New_York

# 2. поиск и веер на одной минуте (проверка работоспособности)
python scripts/stage2_search.py

# 3. walk-forward (первый тестовый месяц, шаг по минутам) и отчёт; последний аргумент — спред на круг в ценах
python scripts/stage3_run_wf.py 2025-03-01 5
python scripts/stage3_report.py 0.00012

# 4. данные для страницы: окно перемотки [start, end) и название инструмента
python scripts/stage4_export.py 2026-08-30 2026-09-01 "EURUSD"
# открыть web/index.html (рядом должен лежать web/data.js)
```

Для FX также стоит выставить `Config.day_start_hour = 17` при `market_tz="America/New_York"`
и уменьшить `atr_long` (7200 минут ≈ 5 суток только для рынка 24/7).

## Устройство

| файл | что делает |
|---|---|
| `data.py` | загрузка CSV любого разумного формата, проверка: порядок, дубли, OHLC, «иглы», пропуски (внутрисессионные / ежедневный перерыв / выходные), пояс времени. Дыры ≤ 3 мин = минуты без сделок, длиннее — разрыв ряда |
| `features.py` | отпечаток минуты (39 чисел): путь за 60 мин в ATR, волатильность, время суток, расстояние до хая/лоя дня, эффективность движения; исходы на 15 мин |
| `search.py` | точный индекс FAISS, прореживание «не больше одного аналога на 30 минут», только прошлое с известным исходом, веса по близости, веер, живое сужение |
| `validate.py` | помесячный walk-forward против базы «тот же час суток», метрики, бутстрэп по дням |
| `export.py` | окно истории для страницы: веер на каждую минуту, суженные веера для каждого якоря, 5 ближайших аналогов |
| `web/index.html` | страница: свечи (Lightweight Charts), веер градиентом, перемотка, панель метрик, аналоги по тапу |

Все параметры заданы заранее в `config.py` и не подбирались по тестовым исходам.
Единственное, что обучается на прошлых месяцах, — коэффициенты калибровки, которые сжимают
вероятность и ожидаемый ход к базе (`reports/stage3_validation.md`, раздел 3б).

## Итоги на замещающих данных (BTCUSDT, 2024-09 … 2026-08)

Подробно — `reports/stage1_data.md`, `stage2_search.md`, `stage3_validation.md`.

* Полосы веера откалиброваны: на +15 мин попадание 51% и 80% при номинале 50% и 80%.
* Веер против распределения того же часа: +0,2% [+0,1; +0,4] по pinball-лоссу на 15 мин
  и −1,0% на 1 мин. На практике это не лучше базы.
* Сырая вероятность «+1 ATR раньше −1 ATR» самоуверенна: в верхнем дециле ждали 65%,
  реально было 51%. По Brier она хуже монетки. После калибровки остаётся ~10% сигнала,
  и вероятность держится в диапазоне 48–51%.
* Ожидаемый ход несёт слабый, но устойчивый сигнал: ранговая корреляция +0,045, положительная
  во всех 18 месяцах. Валовый перекос при этом ~0,005 ATR на сделку, а издержки 0,05 ATR
  съедают его в 10 раз. Порог, выбранный на первой половине, на второй дал −0,14 ATR/сделку.
* Живое сужение не лучше, чем «текущая цена + обычное приращение для этого часа» (−0,7%).
* Барьер ±1 ATR (ATR60 минутных баров) касается в среднем через 2 минуты, так что вероятность
  барьера описывает ближайшие 2–3 минуты, а не 15.

Ограничения: вход считается по закрытию минуты без проскальзывания; если в одной минуте задеты
оба барьера, это считается стопом; у BTC сделки идут круглосуточно, поэтому проверка выходных
и сессий на этих данных почти ничего не проверяет (см. самотест `scripts/test_loader_mt4.py`).
